## 4. 🔴 核心教训（必读）

### ❌ 错误判断：C 方案最初结论
> "3 个上传目录压缩包 HTTP 200 可匿名下载 → 敏感文件可匿名访问 · 信息泄露 · 中危候选成立"

### ✅ 真相
仅看 HTTP 状态码 200 严重不足。`httpx HEAD` 看不出 body 内容，必须用 **GET + Content-Type** 或 **GET + Range(前几字节) + Content-Type** 验证。

| URL | 状态码 | Content-Type | 实际 body |
|---|---|---|---|
| `bocupload/2025/12/11/*.zip` | 200 | **`application/zip`** | 真 ZIP（官方客户端） |
| `bocupload/2025/03/18/*.rar` | 200/206 | **`application/x-rar-compressed`** | 真 RAR（商业软件） |
| `bocupload/2025/08/02/*.rar` | 200 | text/html | **404 HTML（文件不存在）** |
| `images/.../*.rar` | 200 | text/html | **404 HTML（文件不存在）** |

服务端有个**典型配置错误**：对不存在的路径返 **HTTP 200 + 404 HTML 模板**（而非真 404），导致仅看状态码全部判 200，造成"全部可下载"的假象。

### 💡 正确判定（重要）
- **HTTP 200 + 公开/商业软件 Content-Type** → 正常业务分发，**不是漏洞**
- **HTTP 200 + text/html + body 含"404/未找到"字样** → 服务端配置错误，**低危**，非信息泄露
- **HTTP 200 + 源码/数据库/内部文档 Content-Type 或敏感文件名** → **真信息泄露**

### 🛠 工具坑（已记入 05）
- `httpx v1.10` silent 模式 `-sc/-cl/-ct/-body` **不显示内容**（输出兼容问题）
- `httpx v1.10` **不支持 `-body-size`**（EXIT=2）
- `httpx -method HEAD` **无 body**，无法验证 content-type/title/body 实际内容
- **正确做法**：去掉 silent + 去掉 -method HEAD（用 GET）+ 加 `-header "Range: bytes=0-99"` 仅下载前 100 字节 + `-ct` + `-title`

## 7. 留档价值
本次虽然没挖到漏洞，但留下了：
- gau v2.2.4 不支持 `-subs`/`-o`/`-retries`（用 stdin 批量 + safe_exec `--stdin-file`）
- safe_exec 加 `--stdin-file`（透传文件作 stdin 给工具）
- safe_exec 编码 bug 修复（`errors="replace"` + `r.stdout or ""`）
- httpx v1.10 输出兼容坑（silent 不显示元数据、不支持 -body-size、需 Range header + 非 silent）
- **核心方法论：HTTP 200 + Content-Type + Body 类型必须一起判，单看状态码会误判**
