# 03 · 补天提交全流程手册

> 从认领任务到提交成功的逐字段对照。照着填即可，不用怕填错。

---

## 3.1 提交前准备

1. 回公益活动页 → 认领「示例科技」任务（记下**活动名**和**任务名**）。
2. 确认任务状态是「收取漏洞」——若显示「暂不收取」，先别交，等开放。
3. 准备好证据截图（浏览器访问 81 端口的页面）+ 端口扫描结果。

---

## 3.2 字段填写对照表（example-a 实例）

| 表单字段 | 怎么填 | 实例值 |
|---|---|---|
| 厂商名称 | 自动带出 | 示例科技有限公司 |
| 漏洞类别 | 下拉选 | Web漏洞 |
| 漏洞标题 | 一句话说清 | 示例科技有限公司 Nginx Proxy Manager 管理后台暴露公网 |
| 漏洞URL | 可+添加多个 | `http://www.example-a.com:81/` 等 5 个（同源同害一起写） |
| 漏洞类型 | 下拉选 | 事件型 → **配置错误** |
| 漏洞等级 | 保守定级 | **中危**（未实测登录就不写高危） |
| 选择参与的活动 | 回任务页看名字选 | （按实际活动名） |
| 选择参与的任务 | 下拉选 | 人生第一洞-热浪新程 |
| 简要描述 | 中性、不暗示利用 | 见 3.3 |
| 详细细节 | 复现步骤+证据 | 见 3.4 |

| 修复方案 | 写清处置建议 | 见 3.5 |
| 所属行业 | 国标大类 | 信息传输、软件和信息技术服务业 |
| 行业分类 | 子类 | 互联网和相关服务 |

---

## 3.3 简要描述（可直接复制）

```
示例科技有限公司多个子域的 81 端口暴露 Nginx Proxy Manager 管理后台，
未授权用户可直接访问该管理界面。该入口若存在认证缺陷，可能被利用修改反向代理
规则、SSL 证书等关键配置，造成更大影响。本次仅确认界面暴露，未进行任何登录尝试。
```

> ⚠️ 不要写"攻击者可暴力破解/弱口令"这类暗示后续利用的话，会被误读。用"若存在认证缺陷，可能被利用"这种中性表述。

---

## 3.4 详细细节（可直接复制）

```
【漏洞描述】
厂商多个子域（www/h5/video/subadmin/superadmin.example-a.com）的 81 端口运行
Nginx Proxy Manager 管理后台，且对公网开放，未授权即可访问。

【复现步骤】
1. 浏览器直接访问 http://www.example-a.com:81/
2. 页面标题为"Nginx 代理管理器"，返回其默认前端页面（当前显示 API 不健康）
3. 同样方式访问其余 4 个子域 :81 端口，均返回同一管理后台

【PoC】
无需代码，直接访问 URL 即可复现。验证命令：
  curl -sI http://www.example-a.com:81/

【影响】
管理后台暴露可能导致反向代理配置、SSL 证书被未授权篡改。
```

---

## 3.5 修复方案（可直接复制）

```
1. 在网络层限制 81 端口仅允许内网/运维 IP 访问（防火墙或安全组封禁公网 81）；
2. 为 Nginx Proxy Manager 管理后台增加强认证（非默认口令 + 2FA）；
3. 若无需公网管理，建议将管理端口改为非标准端口并仅监听内网；
4. 部署访问审计与异常登录告警，定期复盘暴露面。
```

---

## 3.6 证据要求（审核要"代码/截图/视频"）

- **代码**：不是攻击代码，贴 `curl -sI` 命令或"直接访问 URL 即可复现"即可。
- **截图**（必须有）：浏览器地址栏 + 页面，证明管理后台暴露。**不要截登录成功/输密码的画面。**
- **视频**："必要时"才要，本类配置错误用截图+文字足够，**不录视频**。

---

## 3.7 提交后

- 状态变「补天审核中」，编号形如 `QTV4-2026-xxxxxxx`。
- **立即停止对该目标的一切探测**（已提交=已确权，再扫算攻击）。
- 关注站内信，审核员要补材料再补。
- 本地证据文件别删，复核可能用。
