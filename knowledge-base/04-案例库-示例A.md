## 4.2 扫描执行（轻量、非侵入）

| 步骤 | 工具 | 命令要点 | 结果 |
|---|---|---|---|
| 1 授权验证 | scope_validator | example-a.com→ALLOW / out-of-scope.example→DENY | ✅ 闸门正常 |

## 4.3 核心发现

**Nginx Proxy Manager 管理后台暴露公网（81 端口）**

证据：`http://www.example-a.com:81/` 页面标题 `Nginx 代理管理器`，返回默认前端（显示"API 不健康"）。

受影响 5 个子域：
```
http://www.example-a.com:81/
http://h5.example-a.com:81/
http://video.example-a.com:81/
http://subadmin.example-a.com:81/
http://superadmin.example-a.com:81/
```

定级：**中危**（保守，未实测可登录）。

## 4.5 本次踩的坑（经验沉淀）

1. **提交前务必确认任务状态**：表单显示"厂商资产范围：暂不收取漏洞"——若任务真暂停就别交。
2. **活动下拉必须选**：「选择参与的活动」容易漏，回任务页看活动名。
3. **截图要含地址栏**：只看页面不够，地址栏显示 `:81` 才是铁证。
4. **描述别暗示利用**：写"若存在认证缺陷可能被利用"而非"可暴力破解"。
5. **81 端口 NPM 报错页也算证据**：即使后端 API 不健康，前端暴露本身就构成漏洞。
