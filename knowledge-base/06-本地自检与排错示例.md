# 06 · 本地自检与排错示例

> 用途：在**不扫描任何第三方授权资产**的前提下，验证 nmap / Burp 等本机工具是否被正确接入 skill、
> 合规闸门是否生效、工具是否能正常运行。每次接入新工具或换环境后跑一遍即可。

---

## 6.1 什么时候用这篇

- 刚把新工具（nmap / Burp / php / docker…）接进 `tools.yaml`，想确认 skill 能发现它；
- 怀疑 `scope.yaml` / `tools.yaml` 配置改坏了，想快速验证闸门与解析；
- 想给新手演示"合规闸门只认授权、不认 IP"这一铁律；
- **任何不希望触碰外网域名的场景**（例如已提交审核中的目标不能再扫）。

> ⚠️ 本篇全部命令都只涉及本机回环（127.0.0.1）或越权目标（被闸门拦下，零流量），
> 不对外网发送任何请求，纯本地自检，安全合规。

---

## 6.2 自检脚本（复制即跑）

```bash
PY="python"
SK="$BUTIAN_ROOT"
export BUTIAN_TOOLS_BIN="$(go env GOPATH)/bin"

# ① 工具发现：find_tool + load_registry
"$PY" - <<'PYEOF'
import sys
sys.path.insert(0, "$BUTIAN_ROOT/scripts")
import safe_exec
print("nmap 解析路径 ->", safe_exec.find_tool("nmap"))
print("httpx 解析路径 ->", safe_exec.find_tool("httpx"))   # 应指向 Go 版，非 venv 的 Python 包
reg = safe_exec.load_registry()
print("Burp 上游代理 ->", repr(reg["proxy"]))
print("nmap extra_paths ->", reg["extra_paths"].get("nmap"))
PYEOF

# ② 合规闸门：越权目标必须被拒（不发任何流量）
"$PY" "$SK/scripts/safe_exec.py" --tool nmap --target out-of-scope.example --scope "$SK/config/scope.yaml" -- --version
echo "out-of-scope.example 退出码=$?   (应为 1=拒绝)"
"$PY" "$SK/scripts/safe_exec.py" --tool nmap --target 127.0.0.1 --scope "$SK/config/scope.yaml" -- --version
echo "127.0.0.1 退出码=$?  (应为 1=拒绝，证明闸门不看 IP 只看授权)"

# ③ 本机功能自检：直接对 127.0.0.1 跑 nmap（你自己机器，零外联，安全）
NMAP=$("$PY" -c "import sys; sys.path.insert(0,'$SK/scripts'); import safe_exec; print(safe_exec.find_tool('nmap'))")
"$NMAP" -Pn -T2 --top-ports 15 127.0.0.1 2>&1 | head -20
```

---

## 6.3 预期输出与判定标准

| 检查项 | 预期结果 | 说明 |
|---|---|---|
| `nmap 解析路径` | 指向本机 nmap（如 `E:\pentest\tools\nmap\nmap.EXE`） | `find_tool` 经 BUTIAN_TOOLS_BIN→GOBIN→tools.yaml extra_paths→PATH 找到 |
| `httpx 解析路径` | 指向 `gopath/bin\httpx.exe`（Go 版） | **关键**：必须不是 venv 里的 Python `httpx` 包，否则扫描静默失效 |
| `Burp 上游代理` | `'http://127.0.0.1:8080'` | 来自 `tools.yaml` 的 `proxy` 字段 |
| `out-of-scope.example` 退出码 | `1` | 越权目标被闸门拒绝 |
| `127.0.0.1` 退出码 | `1` | **即使本机回环，不在白名单也拦**——证明闸门基于授权而非 IP |
| 本地 nmap 扫描 | 正常返回端口状态，退出码 `0` | 工具功能正常 |

## 6.5 Burp 代理启用逻辑（补充，本篇未实跑）

Burp 抓包需要 Burp 在跑 + 一个合法目标，本地自检不触发。其启用逻辑：

```bash
export BUTIAN_PROXY_AUTO=1     # 或显式 BUTIAN_PROXY=http://127.0.0.1:8080
# 然后跑 httpx / nuclei，safe_exec 会自动：
#   1) 给命令加 -proxy http://127.0.0.1:8080
#   2) 设 HTTP_PROXY / HTTPS_PROXY 环境变量
#   3) 在审计日志记一条 PROXY 事件
# 不设该变量则直连，扫描不受影响；Burp 没开也不会报错（仅该次请求失败）
```

> 注意：skill **只把流量导给 Burp 做抓包/改包**，**不会**自动驱动 Burp 去扫描。
> 深度自动驱动需 Burp Pro + Montoya 扩展暴露 REST API，当前未做。

## 6.6 常见故障对照（本地自检视角）

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `nmap 解析路径 -> MISSING` | nmap 不在 PATH 也不在 tools.yaml extra_paths | 在 `tools.yaml` 的 `nmap.extra_paths` 补本机路径，或加进用户 PATH |
| `httpx` 指向 venv 的 Python 包 | PATH 顺序导致 venv Scripts 在前 | 设 `BUTIAN_TOOLS_BIN=$(go env GOPATH)/bin`，或把 gopath/bin 提到 PATH 更前 |
| `out-of-scope.example` 退出码 `0` | 闸门坏了 / scope.yaml 被误改宽 | 立刻停手，检查 `scope_validator.py` 与 `scope.yaml` |
| 本地 nmap 扫描卡住 | 本机有安全软件拦截 nmap 发包 | 换 `-sT` 或缩短端口范围；确认是本地可执行问题而非 skill 问题 |
| 设了 `BUTIAN_PROXY_AUTO=1` 但工具报连接拒绝 | Burp 没开 | 先开 Burp 监听 8080，或去掉该变量直连 |
