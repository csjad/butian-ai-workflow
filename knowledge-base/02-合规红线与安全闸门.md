# 02 · 合规红线与安全闸门

> 这是整个工作流的底线。任何一次扫描前都过一遍这一章。

---

## 2.1 授权范围闸门（scope.yaml）

`config/scope.yaml` 是**唯一**允许扫描的资产白名单。改它必须人工确认。

```yaml
# 示例（真实提交前替换为你认领的授权资产）
authorized_targets:
  - domain: "example-a.com"
    scope: "*.example-a.com"
    note: "补天公益任务-示例科技，授权范围内"
```

**验证脚本**（扫之前必跑）：

```bash
PY="python"
$PY scripts/scope_validator.py --target example-a.com --scope config/scope.yaml   # → ALLOW
$PY scripts/scope_validator.py --target out-of-scope.example     --scope config/scope.yaml   # → DENY
```

实测：`example.com`→ALLOW、`out-of-scope.example`→DENY；`safe_exec` 对越权目标**拒绝启动任何工具、不发任何流量**。

---

## 2.2 不可逾越的红线（违反即停手）

| 红线 | 说明 | 后果 |
|---|---|---|
| ❌ 扫域外资产 | 只碰 scope.yaml 里的域名/IP | 可能构成非法入侵 |
| ❌ 登录/试口令/爆破 | 不碰任何登录框、不爆破 | 越权访问，违法 |
| ❌ 发 payload / 拖库 / 提权 | 只读探测，不改数据 | 破坏性利用，违法 |
| ❌ DoS / 高压扫描 | 限速：rl≤50、top-100 端口、深度≤2 | 影响业务，违法 |
| ❌ AI 自动提交 | AI 只出草稿，人手动提交 | 失去人工复核，失控 |

---

## 2.3 安全控制措施（已验证可用）

- `safe_exec.py`：所有工具经它启动，**先过 scope 闸门再执行**，并记录审计日志。
- `kill_switch.py`：一键熔断，状态 `INACTIVE`（验证过）。怀疑失控立即跑。
- `audit_logger.py`：每次执行留痕（时间/工具/目标/结果）。
- `safe_poc_runner.py`：只读 PoC，禁止任何写操作。

---

## 2.4 法律边界（放心，但守规矩）

1. **授权范围内 + 非侵入 = 合法合规测试**，不构成非法入侵。
2. **填错表单 ≠ 违法**：定级写高/写低、描述不精准，最多打回重填。
3. 真正违法的只有：**超范围扫、破坏性利用、拖库提权**——这些我们一律不做。
4. 提交后停止一切探测，等平台结论。
