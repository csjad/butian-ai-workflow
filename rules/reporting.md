# 报告规则（reporting.md）

## 1. 草稿，不提交

- AI 产出的所有漏洞均为**草稿**，供人工审阅。
- **绝不**自动调用平台 API 提交；提交动作只能由用户在平台侧手动完成。

## 2. 报告必须包含

每条发现至少包含：
- 目标（域名/IP/路径）+ 是否在授权范围内；
- 漏洞类型（OWASP / CWE 编号）；
- 严重程度（critical/high/medium/low/info）；
- CVSS 向量与评分（如适用）；
- 证据链（请求/响应摘要，已脱敏）；
- 可复现步骤（最小化、无害）；
- 置信度（0-1）+ AI 判定依据；
- 修复建议；
- 时间戳与扫描任务 ID（便于审计追溯）。

## 3. 置信度与质量门

- 置信度 < 0.7 的发现标记为 `human_review`，不直接进报告正文。
- 通过 7-Question Gate：
  1. 是否在授权范围内？
  2. 是否真实可利用（非理论）？
  3. 是否有明确证据？
  4. 严重程度评估是否客观？
  5. 是否违反平台规则？
  6. 是否可能影响可用性/隐私？
  7. 复现步骤是否清晰、无害？
- 任一不过 → 不写入正式报告，转为待确认。

## 4. 脱敏

- 报告中不得包含 API Key、密码、Token、个人信息（PII）。
- 截图/响应体需打码敏感字段。

## 5. 格式

- 默认 Markdown（便于审阅与复制）。
- 可选 HTML（含图表），由 `report_renderer.py` 生成。
- 支持补天 / 漏洞盒子 / CNVD 等平台差异模板（见 `report-draft` skill）。
