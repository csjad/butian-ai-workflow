# 狩猎规则（hunting.md）

## 0. 目标风险分级（★ 定级先于一切动作）

不同目标类别的法律风险与允许强度差异巨大，**必须先定级再配置 scope**：

| 级别 | 目标类别 | 法律依据 | 允许强度 |
|---|---|---|---|
| **A（最高）** | 政府/部委/政务系统、国防、关基 | **刑法 285 条第 1 款：侵入国家事务领域系统，仅"侵入"即构罪**；《关基保护条例》从重 | 仅精确主机 + 公开页面；并发 ≤5、总请求 ≤200；**禁 Strix 等探索式工具**；夜间窗口；硬排除政务服务路径。**优先建议放弃该目标** |
| **B** | 高校、医院、事业单位 | 285 条第 2 款（需侵入+获取数据） | 单目标受限扫描；硬排除教务/学工/医疗等含个人信息系统 |
| **C** | 企业（含大型集团）、商业站点 | 285 条第 2 款 | 按 scope 常规强度（并发 ≤5~10、请求 ≤500~800） |

**A 级目标附加规则（强制）**：
1. 不使用 `*.domain` 泛域，只放行截图给出的**精确主机**；
2. 必须硬排除 `zwfw`/`zwdt`/`bsdt`/`portal`/`approve`/`12315`/`credit`/`gsxt`/`oa`/`mail`/`sso`/`vpn` 等；
3. **不得运行 Strix 等探索式/攻击性自动化工具**（强度不可控）；
4. 遇到任何防护阻断（WAF 403 / anti-bot JS 挑战 / RST）→ **立即停止，不得绕过**（见 §4）；
5. 平台收录（含"资产范围无限制"）**不等于**该单位对个人的书面授权 —— 部委级目标尤其如此，报告中标明该不确定性。

## 1. 范围与速率

- 每个目标流量前必须通过 `scope_validator.py`。
- 默认速率上限：`nuclei` ≤ 50 rps、`naabu` ≤ 1000 pps；不得超过 scope 中 `rate_limit`。
- 单次任务请求数不得超过 scope 中 `max_requests`。
- 禁止对单个端点高频重放导致服务不可用。

## 1.5 目标预检（★ 60 秒定性，避免无效投入）

在配置 scope 并发起批量扫描前，先做 4 项轻量预检（总计 <10 个请求）：

| # | 检查 | 终止条件（直接结案） |
|---|---|---|
| 1 | HEAD 首页看状态码 | 403 + `X-Via-JSL`/anti-bot Cookie → **防护阻断，硬停止**（见 §5） |
| 2 | 看是否 301/302 跳转到**其他注册域** | 跳转目标域 ≠ 授权域 → **该域为跳转壳，不在范围内，不得跟测** |
| 3 | 看响应体大小 | 302 且 body=0B → **纯跳转，无攻击面，结案** |
| 4 | CT 日志（crt.sh）看子域数 | 仅 1 个名字 + 常见子域抽查全 `000` → 无子域面 |

**注意**：本机 DNS 存在**泛解析假象**（所有子域返回同一 IP，曾出现 203.0.113.10 / 10.x）。判定存活必须结合 CT 日志 + 实际 HTTP 状态码，**不能只信 nslookup**。

**结案标准**：命中上述任一终止条件 → 写报告结案，**不运行 nuclei/Strix**（无意义消耗）。

**配套工具**：`scripts/target_qualifier.py`（目标预筛打分器）
—— 批量对候选域名做单次请求级预检，按「动态面 / 防护强度 / 技术栈年龄 / 资产广度」打分排序，
输出 🔥HIGH / 🟡MID / ⚪LOW / ⛔SKIP 四档表。开工前先跑它，只把时间投给 HIGH 目标。
用法见脚本文件头；评分卡与选目标方法论见工作区 `补天目标筛选评分卡.md`。

## 2. 工具使用

- 仅使用 scope `allowed_tools` 中列出的工具。
- 下列工具默认需人工二次确认（见 `hooks/pre-dangerous-tool.py`）：
  - `sqlmap`（可写/可删）
  - `wpscan`（WordPress 暴力）
  - 任何身份认证绕过/爆破类动作
- 未列出的工具不得擅自调用。

## 3. 禁止的利用行为

- 不执行会修改/删除数据的 payload（INSERT/UPDATE/DELETE/DROP）。
- 不执行 RCE 类实际命令执行（除非目标为自有靶场且授权明确）。
- 不执行 SSRF 内网探测超出授权范围。
- 不执行存储型 XSS 实际注入（用无害 proof-of-concept 替代）。

## 4. 噪声与隐蔽

- 不隐藏来源、不伪造身份绕过风控。
- 扫描应可被审计追踪；保留请求日志。

## 5. 停止条件

出现以下任一情况立即停止并报告：
- `scope_validator.py` 返回 DENY；
- 目标响应异常（5xx 激增、超时飙升）疑似影响可用性；
- 发现疑似生产数据库/大量用户数据；
- `kill_switch.py` 激活；
- 用户明确要求停止。

**★ 防护阻断 = 硬停止（无例外）**：
- 遭遇 WAF 403、anti-bot JS 挑战（如加速乐 `X-Via-JSL` + `__jsluid_s`）、连接 RST 时，
  **立即停止该目标**，不得通过伪装 UA、模拟浏览器、解 JS 挑战等方式绕过；
- 此情形下**同时取消后续模板扫描**（nuclei/Strix 打过去只会产生风控噪音，且调整请求特征本身即越线）；
- 结论按"目标防护有效 + 主动中止"记录，**不作为漏洞提交**。
